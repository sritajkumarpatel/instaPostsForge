Why

Good photos don't post themselves.

You come back from a walk with forty frames and three keepers. Then the keepers sit in a folder, because posting well every day is its own job: pick one, don't repeat last week, write something true, choose the hashtags, remember to do it at all.

instaPostsForge does that job the way you would at a contact sheet. It looks at every frame in your Drive folder once, circles the one for today, and writes the caption. It runs on GitHub Actions, so no server and no laptop need to stay on.

Prefer your phone? Postaday is its Android sibling and runs the same workflow with your own keys.

A day with instaPostsForge

One scheduled run, a few minutes, one post.

The Daily post workflow starts at 13:30 UTC (7:00 pm IST) once the AUTO_POST variable is on. Change the time in one cron line. The minutes below are typical, not fixed.

How it works

Five Claude agents, with code at every gate.

The AI decides what to post and what to say. Plain code does everything with a side effect (fetching, image preparation, hosting, publishing, records) and validates every answer before it can reach Instagram. Every agent runs on Claude Haiku 5.5 by default, or on OpenAI or Gemini by setting one variable.

ANALYST ▸ PLANNER ▸ RULES ▸ CAPTION WRITER ▸ HASHTAGS ▸ REVIEWER ▸ CHECKS ▸ INSTAGRAM     ANALYST ▸ PLANNER ▸ RULES ▸ CAPTION WRITER
  1. analyst

    Describes each new photo once: category, mood, main subject, quality from 1 to 10, anything unsafe.

  2. planner

    Picks today's photo or set, balancing strong photos with variety and what has performed well.

  3. code: rules

    No explicit photos, screenshots or children. No near-duplicates, no subject twice in 3 days, no mood more than twice a week.

  4. caption_writer

    Writes the caption, a quote when one fits, and alt text. Code holds the text to 150 characters.

  5. hashtags

    Chooses 3 to 5 specific tags, rotating away from recent sets.

  6. reviewer

    Approves, or sends back only the part it faults, up to two times.

  7. code: checks

    At most 5 hashtags and 2,200 characters, JPEG, 4:5 to 1.91:1. A false claim or a doubtful quote author skips the day.

A workflow, not an agent

Prompt chaining with gates and an evaluator-optimizer review loop. The model gets no tools and chooses no steps.

It fails safe

If the planner fails, a random eligible photo is used. If the review still finds a real problem, the day is skipped. A broken post never goes out.

Never twice

A photo is recorded only after Instagram returns a media ID, keyed by a hash of its Drive file ID, together with every photo of a set.

Token audit

Know exactly where the tokens go.

Every Claude call is written to state/<profile>/usage/ as it happens, whether it succeeds or fails, with its model, input, output and cache tokens, time taken and estimated cost.

After every post, preview or plan run, scheduled or manual, the workflow saves a token audit report as a run artifact, kept for 90 days. It shows:

  • tokens, cache use, seconds, failures and cost per phase and per agent;
  • every call in order, so a revision or a shortening pass gets its own row;
  • the month so far, by phase.

forge usage -p main totals any month from the command line.

Privacy and safety

A public repo that holds nothing private.

Instagram

Official API only. It uses an access token you create and can revoke. It never asks for your Instagram password.

Secrets

Only in GitHub secrets. Keys, tokens and the Drive folder link are passed only to the step that runs forge, never to installs or third-party actions.

Photos

No EXIF, no GPS. Published JPEGs carry only the colour profile. GPS is compared in memory to group outings and never saved. Photos are recorded by a one-way hash of their file ID.

Content

Rules in code. Explicit photos, screenshots and photos with children are skipped, and addresses and number plates stay out of the text.
